# ADR 0007: 制作计划确认策略

## 状态

Accepted

## 背景

`dahei-ppt` 的主入口是一段讲稿或文案，系统会自动拆解为页面和镜头。自动拆解可能误判重点、视觉主角或页面数量。提前确认制作计划可以减少返工。

## 决策

默认确认制作计划。

规则：

- 复杂内容先展示制作计划，再生成 HTML。
- 简单内容可以直接生成 HTML，同时保留制作计划。
- 用户明确要求快速产出时，可以跳过确认。
- 用户对制作计划提出修改后，再进入 HTML 生成。

## 制作计划必须包含

- 原文片段
- 页面标题或主文案
- 视觉主角
- 语义类型
- 推荐模板
- 注意力路径
- 退场策略
- 预计时长

## 影响

- 生成流程分为计划阶段和实现阶段。
- 制作计划成为可编辑中间产物。
- 质量检查先检查制作计划，再检查 HTML 视觉。

## 待继续追问

- 制作计划用 Markdown、YAML，还是两者都输出。
- 用户确认时最需要看哪些字段。
- 是否需要为每页生成缩略草图描述。
