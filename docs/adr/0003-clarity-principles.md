# ADR 0003: 清楚优先原则

## 状态

Accepted

## 背景

`dahei-ppt` 的核心价值来自把内容讲清楚。美观、特效和趣味都服务理解。一个优质页面应当让观众迅速知道先看哪里、接着看哪里、最后记住什么。

用户的剪辑原则是“切到不能再切”。如果删掉一句话、一个元素或一个页面，逻辑仍然成立，它就倾向于被删除。这个原则应进入 HTML 生成、分镜拆解和 MP4 渲染的所有阶段。

## 决策

`dahei-ppt` 的生成优先级为：

1. 精简
2. 讲清楚
3. 美观
4. 有趣

每个页面或镜头都必须先回答：

- 删到只剩什么依然成立？
- 这一页的唯一主角是什么？
- 观众第一眼看哪里？
- 观众第二眼看哪里？
- 观众最后应该记住什么？

## 页面生成规则

- 每页只允许一个主角。
- 多个主角进入多页。
- 陪衬元素可以存在，但承担解释环境、关系或氛围。
- 陪衬元素的视觉强度必须低于主角。
- 主角出现、移动、替换或被连接时，观众注意力应随之迁移。
- 页面文字以关键词和结构为主，解释交给旁白。
- 页面元素数量达到理解负担时，优先拆页。

## 影响

- 模板系统需要声明“视觉主角”字段。
- 制作计划需要声明“注意力路径”字段。
- 质量检查需要加入“主角唯一性”和“删减测试”。
- 好看的风格迁移只能发生在不削弱视觉中心的前提下。

## 样本观察

### 样本 1：中心模型页

主角是中心的 `Step3.5Flash`。周围的角色定义、工具调用、上下文、技能知识、权限治理都是陪衬。页面通过大小、位置、字重、留白和半透明背景让视线集中在中心模型上。

可吸收规则：

- 中心大主角 + 周边低强度标签。
- 顶部保留一句短判断。
- 背景图形只做体量感和层次感。
- 陪衬标签分布在主角周围，表达“能力围绕主角展开”。

### 样本 2：后端 / 前端对照页

主角是左右两侧的结构差异。页面通过垂直中线、双标题、左右视觉块建立对比。左侧参数输入，右侧聊天界面，理解路径很短。

可吸收规则：

- 左右对比适合讲“两个系统如何对应”。
- 大标题先给分类，再用少量大字段支撑理解。
- 橙色只标出标签或关键动作。
- 中线建立关系，也建立阅读边界。

## 待继续追问

- 主角的类型列表如何定义：词、图、设备、关系节点、流程步骤、截图区域。
- 注意力迁移的默认动效如何设计：出现、移动、聚焦、连接、替换。
- 页面拆分阈值如何设定：主角数量、文字量、关系数量、视觉密度。
