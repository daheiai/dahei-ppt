# ADR 0002: 输入契约

## 状态

Accepted

## 背景

`dahei-ppt` 过去的高质量产出依赖详细画面描述：创作者需要说明每页内容、布局、素材位置和动效顺序。这个模式质量可控，但效率提升有限。

升级后的核心价值来自内容拆解：创作者提供一段讲稿或文案，系统自动拆成画面段落、选择模板、生成 HTML，并导出 4K60 MP4。

## 决策

`dahei-ppt` 的主入口改为“一段讲稿或文案”。

系统负责完成：

1. 识别文案中的观点、转折、例子、对比、结论。
2. 拆成 1 到多个画面段落。
3. 为每个画面段落选择模板。
4. 生成 3:2 高质量 HTML。
5. 基于 HTML 导出 4K60 MP4。

用户仍可补充画面偏好、素材、参考风格和局部要求。这些信息作为约束输入，优先级高于自动拆解结果。

## 影响

- 内容拆解成为第一阶段能力。
- 模板库需要服务语义类型，而只服务页面类型。
- 生成流程需要先输出制作计划，再进入 HTML 实现。
- 每个制作计划都要保留可人工修改的结构化文件。
- 高质量 HTML 仍是主源文件，MP4 是导出物。

## 初始语义类型

第一批内容语义类型：

1. 核心观点
2. 概念定义
3. 时间演化
4. 因果关系
5. 对比判断
6. 案例展示
7. 数据说明
8. 结论收束

## 待继续追问

- 文案拆解时，系统应优先追求信息完整、观看节奏、视觉冲击，还是后期剪辑灵活度。
- 每个画面段落的默认时长应由文案字数、模板类型、或创作者习惯决定。
- 制作计划是否需要作为每次生成前的确认步骤。
