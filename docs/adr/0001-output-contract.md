# ADR 0001: 输出契约

## 状态

Accepted

## 背景

`dahei-ppt` 当前擅长生成适合录屏的 3:2 HTML 演示画面。升级方向需要保留这种可控的网页画面，同时减少手动录屏和重复调节的成本。

用户当前工作方式是按视频小片段进行创作：提供一段具体意图、画面设想、布局要求，再由 skill 生成对应 HTML。这个方式质量可控，但创作者需要自己承担大量分镜和布局思考。

## 决策

升级后的 `dahei-ppt` 第一优先输出两类交付物：

1. 高质量 3:2 HTML：用于人工检查、截图、手动录屏和继续调整。
2. 4K60 MP4：由 HTML 渲染生成，用于直接进入剪辑流程。

HTML 保持手动控制节奏。方向键、空格、回退键仍然是核心交互方式。

MP4 渲染流程可以使用内部时间轴、逐帧截图或等价机制。时间轴服务渲染，不改变 HTML 的主要使用方式。

## 影响

- 3:2 是固定画幅约束。
- HTML 是主源文件，MP4 是可复现导出物。
- 自动播放可以作为渲染内部机制，用户面对的主要预览方式仍是手动控制。
- 内容拆解系统应先服务“小片段生成”，再扩展到完整视频。
- 参考项目的经验优先吸收为：分镜结构、模板系统、渲染链路、设计检查。

## 待继续追问

- 用户希望输入到 skill 的最小单位是什么：一句观点、一段讲稿、一个画面描述，或一个完整镜头组。
- 4K60 渲染的默认节奏由谁决定：模板默认、用户文本指定、或生成后人工改配置。
- 是否需要每次导出同时生成关键帧拼图，方便快速审片。
