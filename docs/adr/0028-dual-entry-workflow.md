# ADR 0028: 双入口工作流

## 状态

Accepted

## 背景

`dahei-ppt` 需要服务两种不同创作场景：

1. 用户提供完整视频文案，希望 AI 帮忙做整体画面形态规划。
2. 用户已经确定某一小段要做动画，希望直接进入动画制作流程。

这两种场景的判断成本不同。完整文案需要先分区；动画小段不需要再判断人物出镜、拍摄或网络素材。

## 决策

`dahei-ppt` 支持双入口：

1. 整片规划入口：完整文案 -> 画面形态计划。
2. 动画制作入口：动画小段 -> 制作计划 -> HTML -> MP4。

## 整片规划入口

输入：

- 完整视频文案

输出：

- 画面形态计划

用途：

- 判断每段适合人物出镜、动画、网络现场素材，还是拍摄。
- 给用户提供整体制作建议。
- 用户可在 Studio 中按颜色直接修改分区。

## 动画制作入口

输入：

- 已确认要做动画的一小段文案

输出：

- 制作计划
- `slides.html`
- `render.html`
- `exports/render.mp4`

用途：

- 跳过画面形态分流。
- 直接生成动画段落。

## Studio 交互

Studio 对整片规划入口提供颜色分区编辑器：

- 绿色：人物出镜
- 红色：动画
- 黄色：网络现场素材
- 紫色：拍摄

用户可以直接在网页编辑器中调整段落颜色。颜色调整会更新 `visual_mode`。

整片规划入口的段落边界遵循 ADR 0030。动画段落可以直接派生为动画制作片段。

## 项目关系

完整视频项目保存总文案和画面形态计划。动画制作片段保存在完整视频项目的 `segments/` 下，也可以作为独立项目创建。

```text
studio/projects/2026-xx-video/
  script.md
  visual-routing.md
  visual-routing.yaml
  segments/
    segment_03-animation/
      script.md
      production-plan.md
      production-plan.yaml
      slides.html
      render.html
      assets/
      exports/
```

## 影响

- Studio 需要两个入口按钮或两个工作模式。
- 画面形态计划和动画制作计划是两个不同层级。
- 完整文案项目可以包含多个动画小段。
- 动画小段可以独立创建项目，也可以挂在完整视频项目下。
