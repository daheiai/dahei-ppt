# ADR 0027: 整片文案的画面形态分流

## 状态

Accepted

## 背景

`dahei-ppt` 当前聚焦“讲稿/文案 -> 动画画面段落”。但完整视频通常包含多种画面形态：动画、人出镜、实际拍摄、网络素材引用。不同内容类型适合不同画面形态。

用户的视频生产中，人出镜是一种保底画面，也能拉近观众关系和建立个人 IP，但主要价值是提高制作速度。原理解释、对比、数字论证更适合动画。小剧场、整活或需要现实感的片段适合实际拍摄。明确引用新闻、产品、网页、历史事件时，适合找网络素材或截图。

## 样本依据

参考样本：

- `docs/research/o3-video-visual-mode-sample.md`

样本来自用户过往视频文案，颜色标注含义为：

- 绿色：人物出镜
- 红色：做动画
- 黄色：找网络现场素材
- 紫色：拍摄

## 决策

完整文案进入系统后，先做画面形态分流：

1. 人物出镜：连接、过渡、主观判断、节目感、结尾互动、保底画面。
2. 动画：结构化解释、抽象变化、对比、数字论证、评分、总结图表。
3. 网络现场素材：新闻引用、产品截图、网页证据、公开画面、模型输出、测试录屏、历史素材。
4. 拍摄：小剧场、实物演示、现实操作、生活情境、整活段落。

## 分流策略

### 人物出镜

适合：

- 开场和结尾
- 章节之间的连接
- 主观判断和态度表达
- 情绪、吐槽、节目感
- 难以动画化且不值得找素材的段落
- 保底画面

判断逻辑：

如果一句话的核心价值来自“我怎么看”“我怎么感受”“我要把观众带到下一段”，优先人物出镜。

### 动画

适合：

- 原理讲解
- 结构关系
- 对比判断
- 数字论证
- 流程说明
- 评分和总分
- 抽象变化和反差

判断逻辑：

如果一句话需要观众看懂“关系、差异、变化、尺度、因果”，优先动画。

### 网络现场素材

适合：

- 模型回答原文
- 实测录屏
- 网页、地图、榜单、截图
- 新闻、公开视频、历史素材
- 明确提到某个外部作品或案例

判断逻辑：

如果一句话的说服力来自“真实证据”或“现场材料”，优先网络现场素材。

### 拍摄

适合：

- 小剧场
- 现实生活场景
- 实物演示
- 操作过程
- 整活段落

判断逻辑：

如果一句话需要现实质感、人物表演或实物操作，优先拍摄。

## 形态优先级

同一段内容可有多个候选形态时，按表达目的判断：

1. 需要证据：网络现场素材
2. 需要讲清结构：动画
3. 需要情绪和连接：人物出镜
4. 需要现实感：拍摄
5. 画面缺口：人物出镜保底

## 画面形态计划

完整文案进入系统后，先生成画面形态计划：

```yaml
segments:
  - id: segment_01
    source: "原文片段"
    visual_mode: "talking_head"
    reason: "开场背景说明，人物出镜更自然"
    animation_candidate: false
```

初始 `visual_mode` 枚举：

- `talking_head`：人物出镜
- `animation`：做动画
- `web_source`：网络现场素材
- `live_shoot`：拍摄

只有 `animation_candidate: true` 或 `visual_mode: animation` 的段落进入动画制作计划。

## 影响

- 完整视频级别需要新增“画面形态计划”。
- `dahei-ppt` 生成动画段落，同时标记非动画段落的素材建议。
- 制作计划需要区分页级计划和整片级画面分流。
- Studio 需要能展示每段推荐画面形态。

## 待继续追问

- 网络现场素材是否需要自动生成素材搜索关键词。
- 人物出镜段落是否需要自动生成提词器文本。
- 拍摄段落是否需要自动生成拍摄清单。
